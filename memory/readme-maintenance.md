# README.md Maintenance Guidelines

## Overview

The main README.md serves as the project's landing page and must remain concise, current, and easy to read while following file size limits.

## Core Principles

### File Size Management
- **Maximum**: 500 lines (documentation file limit)
- **Target**: Keep under 200 lines for optimal readability
- **Strategy**: Essential information only, link to detailed docs

### Content Strategy
- **Landing Page Approach**: First impression for users/contributors
- **Essential Information Only**: What users need to know immediately
- **Link to Details**: Comprehensive info lives in docs/ folder

## Required Sections

### Standard Structure
```markdown
# Project Name
Brief tagline/description

## Overview
2-3 sentences about what the project does

## Quick Start
Minimal steps to get running

## Key Features
3-5 bullet points of main capabilities

## Documentation
Links to detailed documentation in docs/

## Contributing
Brief contribution guidelines + link to full guide

## License
License information
```

### Content Guidelines

**Overview Section:**
- 2-3 sentences maximum
- Clear value proposition
- Avoid technical jargon

**Quick Start:**
- 3-5 essential steps only
- Basic prerequisites
- Link to detailed setup guide

**Features:**
- 3-5 key capabilities
- User-focused benefits
- Avoid implementation details

## Maintenance Patterns

### What to Include
- Project purpose and value
- Quick installation steps
- Essential commands
- Links to comprehensive docs
- Current project status

### What to Avoid
- Detailed API documentation
- Complete feature lists
- Long code examples
- Duplicate information from docs/
- Outdated information

### Link Strategy
```markdown
## Getting Started
Quick setup instructions here...

For detailed setup and configuration, see [docs/getting-started/](docs/getting-started/)

## Architecture
Brief overview...

For complete architecture details, see [docs/architecture/](docs/architecture/)
```

## Regular Maintenance

### Review Schedule
- Update with major releases
- Review monthly for accuracy
- Check links quarterly
- Refresh examples as needed

### Quality Checklist
- [ ] Under 200 lines (target) / 500 lines (max)
- [ ] Current and accurate information
- [ ] Working links to documentation
- [ ] Clear, concise language
- [ ] Essential information only
